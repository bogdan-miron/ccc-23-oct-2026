## Data traps seen (migratory-birds)
- D-001 Number words in numeric columns ("seventeen") in L1 files a and e; fixed in all_data_from_level_1.in. | cio.read_table reports and fixes.
- D-002 Degree F values in the Celsius column only in L1 file e (759 of 2171 rows, values 55..113), announced only by the L2 PDF. Histogram shows a gap around 45..55. F values below 45 hide among valid C (true C below about 7). | rule: later PDFs can reveal traps in earlier data, re-check earlier outputs.
- D-003 L1 file d has one single temperature (19): tie-break rules decide everything. Small files a..d probe edge cases, e is the scale test.
- D-004 L2 files a/b/c partition BOP 1..2500 (1000/1400/100 rows); c is 100% unlabeled. | rule: pool labeled rows across files.
- D-005 all_data_from_level_k = union of the level's inputs with word-numbers fixed; other bugs (F) remain.
- D-006 L4: 360 flocks (288 labeled, 72 fully unlabeled), one species per flock, 45-50 flocks per species, 3-12 rows per flock, 90 duplicate rows. all_data_from_level_4 (used in L5) has all labels filled.
- D-007 L5/L6 panel: 2500 BOPs x 730 days, plus 30 forecast days with missing Arrivals (1.9M rows). Wind is one value per day, Insects Delta is constant per BOP. Arrivals day-to-day autocorrelation 0.96, Occupancy 0.996. Trailing-30-day mean per BOP gives top-50 overlap 0.57 in a backtest (threshold 0.5).
- D-008 L6: 30 new days with Arrivals present, no covariates for day 791, required accuracy 100%.

- D-009 (L6 recon) Adversarial validation on a feature that is constant within a group (wind per day) is degenerate: AUC 1.0 just identifies the day. | rule: compare day-level aggregates / per-feature KS, not row-level classifiers.
- D-010 (L2 recon) Join with L1 data + F fix by range turns ridge RMSE from 13.1 to 2.58 (thresholds 6/3/3). Fixing a data trap beat any model change. | rule: traps first, models second.
- D-011 (L1 e, seen blind from data alone) Histogram of the Temperature column: nothing in 46..54, 759 values in 55..113. Max C seems 45 and 113F = 45C, so these are F. F values under 46 hide among C (about 362 rows below 7), so no exact repair exists at L1. | variant A raw (primary) and B converted (variants/), the upload verdict decides.
- D-012 (L2) The example input/output rows are real rows of the universe: example labels (BOP 1, 2) are missing in b and a, example out (BOP 3, 4) are the true labels (BOP 4 is labeled in a, 42.95). So the exact example check for a regression level is a lookup, not a model test. | rule: pool example labels, and validate the model by CV plus the model-only error on the example rows (25.25/42.85 vs 28.20/42.95).
- D-013 (L2) Label = 1.70 * tempC(fixed) + 14.3 - 0.022 * urban light + 0.010 * humidity + noise(sd 2.58). Vegetation and insects are not significant. Residual is Gaussian, flat, no id structure: the CV RMSE of plain ridge is the floor. | rule: after a linear fit with Gaussian flat residuals, stop; trees, interactions and residual boosting only add variance (2.60, 2.59, 2.62 vs 2.585).
- D-014 (L2, vs L1) L1 file e passed (user, variant A raw) although L2 says F values are errors. So the L1 grader used the raw column. Confirmed by the user: raw was uploaded and passed. | rule: a data fix announced later does not mean the earlier level's expected output changes; keep passed outputs frozen.
- D-015 (L3) Species are fully determined by path shape: palindrome (Bluetit), shorter palindrome on another flock's route (Wolfthroat), identical closed non-palindromic loop (Blackfinch), shared prefix then split (Goldhammer), same nest with disjoint middles (Firefinch), same nest with overlapping middles from hot BOPs, tC about 43.6 (Hurracurra). Hot BOPs: about 40+ C after the F fix. | rule: the story is the feature spec; encode each sentence as a score, then solve the stated one-to-one constraint with an assignment.
- D-016 (L3) Single-row flocks (the example) make "identical rows" trivially true, so rules based on flock-wide equality need a second signal (containment in another flock's route). The exact example check caught it before any upload. | rule: keep running the example through the real solver, it catches rule ties.
- D-017 (L4) Labeled flock counts per species are 45-50 and the 72 unlabeled flocks are predicted as 15/14/12/11/10/10, i.e. exactly 60 per species in total. A classifier whose predicted counts equal "60 minus labeled" is a strong global check. | rule: when the universe looks balanced, compare predicted class counts with the implied missing counts before uploading.
- D-018 (L4) Features that encode the L3 story rules beat generic ones: within-flock relations (common prefix/suffix, sequence ratio, tail overlap, palindrome share), temperature after the F fix (Hurracurra every BOP above 42 C), and the share of consecutive BOP pairs that occur in palindromic flocks. Row count and cross-flock BOP overlap hurt on the truncated example flock and slightly in CV. | rule: unit of CV and of prediction is the flock; do not let features depend on how many rows were sampled.
- D-019 (L4) The example file is a truncated sample (flock 17 has 2 of its rows), so the exact example check can fail for a good model. Here it did, once, and it pointed to features that depend on row count. | rule: when the example fails on a model that CVs well, look at what is atypical in the example (row count, file size) and test whether the feature set that fails it is also worse in CV, then decide.
- D-020 (L5) Ranking target: Arrivals = Occupancy x BOP factor x day factor x slow per-BOP deviation. The day factor cancels inside a day, so model the within-day centered log1p(Arrivals) with log Occupancy of the forecast day (known!) as the main feature. Forecast-day covariates known in the file (Occupancy, wind, insects) are the signal; history alone caps at 0.47 top-50 overlap at lag 30.
- D-021 (L5) Backtests of a 30-day top-50 forecast vary a lot by window (0.32 to 0.83 for simple models, 0.46 to 0.79 for the GBM). | rule: validate on many overlapping windows (9 here), report mean and min, and tell the user the pass probability is not 100%.
- D-022 (L5) Things that did not help: per-BOP regressions on O and wind (0.60), year-ago analog (0.38), BOP id feature, low-rank denoised deviations, candidate restriction, LightGBM vs more trees. Wind helped +0.025 only in the GBM. | rule: stop at the plateau (about 0.64), the remaining error is unpredictable slow deviation.
- D-023 (L5) I had read D-007..D-009 (L5/L6 facts) in LESSONS.md at session start, so L5 and L6 are not fully blind. All L5 numbers above come from this data. | rule: for the next dry run, split LESSONS.md into a spoiler-free log and a separate file for dry-run findings.
- D-024 (L6) The regime shift is an exact time mirror: days 761..790 equal days 760..731 cell for cell (Arrivals, Occupancy), wind negated. The story said "wind opposite, worms backwards". No model needed: the answer for day 791 is day 730 (top 50). | rule: when a PDF announces a regime change, first test exact reversal/negation of the previous block (equality of cells, shift by one day as control) before any model; a "100% required" threshold signals a deterministic rule.
- D-025 (L6) Persistence would have scored about 92% overlap on that day, not 100%. | rule: if the threshold is 100%, a statistical forecast cannot pass; look for the generating rule.
